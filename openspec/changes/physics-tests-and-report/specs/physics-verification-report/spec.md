## ADDED Requirements

### Requirement: Markdown verification report generated after test run
After the Vitest test suite completes, the system SHALL produce a Markdown file (`frontend/physics-report.md`) summarizing every physics test case with its pass/fail status, test name, and duration. The report SHALL be regenerated on every test run (not accumulated).

#### Scenario: Report file is written after test suite completes
- **WHEN** the test suite runs via `npm test` in the frontend directory
- **THEN** `physics-report.md` exists in the frontend directory after the run completes

#### Scenario: Report reflects latest test run results
- **WHEN** the test suite is run a second time after a previous run
- **THEN** the report contains only the results from the most recent run (no duplicate sections)

### Requirement: Report structure and sections
The Markdown report SHALL follow a defined structure with a header, summary table, and per-test-suite sections.

#### Scenario: Report contains a summary block
- **WHEN** the report is generated
- **THEN** the report's header section includes: total tests, passed count, failed count, and run timestamp in ISO 8601 format

#### Scenario: Report contains one section per describe block
- **WHEN** the report is generated
- **THEN** each `describe(...)` block in `physics.test.ts` appears as a `##` heading in the report, with its test cases listed beneath it

#### Scenario: Each test case row shows pass/fail status
- **WHEN** the report is generated
- **THEN** each test case is rendered as a table row or list item with: status icon (✅ pass / ❌ fail), test name, and duration in milliseconds

#### Scenario: Failed tests include error message
- **WHEN** a test fails and the report is generated
- **THEN** the failed test's entry includes the assertion error message so the reviewer can diagnose without re-running tests

### Requirement: Report is generated by a Vitest custom reporter
The report SHALL be produced by a TypeScript file implementing the Vitest `Reporter` interface, registered in `vitest.config.ts`. It SHALL NOT require a separate post-processing command.

#### Scenario: Reporter failure does not fail the test suite
- **WHEN** the reporter encounters a file-write error (e.g., permissions)
- **THEN** the test suite exit code reflects only test pass/fail, not the reporter error

#### Scenario: Reporter is registered in vitest config
- **WHEN** `npm test` is executed
- **THEN** both the default Vitest console output and the Markdown reporter run concurrently

### Requirement: npm script for report generation
A `test:report` npm script SHALL be added that runs the full test suite and confirms the report was written.

#### Scenario: Running test:report produces the report file
- **WHEN** `npm run test:report` is executed in the frontend directory
- **THEN** `physics-report.md` is present in the frontend directory after the command exits
